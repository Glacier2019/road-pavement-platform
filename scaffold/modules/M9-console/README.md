## 五、页面与取数口径

| 页面 | 路径 | 取数 |
|---|---|---|
| 首页 | `/` | `/gw/v1/modules/status` |
| 表盘点 · 缺口归因 | `/tables` | `/gw/v1/catalog/tables` ＋ `/gw/v1/catalog/gaps` |
| 几何查询 | `/geometry` | `/gw/v1/geometry/*` |
| 三维起伏 · 鸟瞰 · 沿程量 | `/sim` | **不走 `/gw`**：交付目录 `artifacts/sim/`（只读挂载） |
| 设计导入 | `/import` | 写走 **自己的端点**，不借 `/gw`（`/gw` 是只读的） |

**页面一律经 `/gw` 取数，M9 永不直连数据库**（三条硬线之「读只经 M3 rpdao」）。
`/gw` 只转发 `v1/` 前缀下的 GET，且**只读** —— 一个无限制的转发器等于把 M9 变成任意 URL 抓手。

**唯一例外是 `/sim`**：它读的是**本模块自己的交付资产**（路面网格，从库中数据离线再生），
不是别人的业务数据，所以既不经 `/gw`、也不碰数据库 —— 它读文件。
`/artifacts/{name}` 是**白名单路由**：只认清单 `manifest.json` 里登记且 `present: true`
的名字。目录里存在但未登记的文件取不到，路径穿越在查表这一步就失败了，
**根本没有机会拼路径**。

`/sim` 一页承担四件事，共用同一份交付目录：

| 能看到什么 | 数据来自 | 清单里对应的 `kind` |
|---|---|---|
| 路面三维鸟瞰（两个细节层级） | `terrain_*.bin` | `terrain_mesh` |
| 车沿路走的轨迹与朝向 | `wheel_loads.csv` | `vehicle_track` |
| 沿程量着色（高程 / 轮荷 / 曲率） | 网格中线 ＋ 轨迹 | 同上 |
| 两段仿真视频（10× 与实时） | `*.mp4` | `video` |
| 坐标基准与它的假定 | `config/crs.yaml` | —— （本模块自己的配置） |

> 清单里 `present: false` 的条目**不是错误**：它表示「这条契约说了要有、但现在还没产出」。
> 页面据此显示「未产出」，不报错。这样契约可以先于产物存在 ——
> 两段视频就是在契约写完之后才补上的，`kind: "video"` 早已在 schema 的枚举里。

### 三维起伏页的三处刻意的取舍

1. **垂直放大默认真尺度，且倍数常驻显示**。这条路平面约 5.5 km、高差 29.75 m
   （1:185），真尺度下画面几乎是平的。默认放大更好看，但一张截图拿出去就会被
   当成真实纵坡 —— 所以默认 1.0，并把「这是尺度的性质，不是数据的问题」写在页面上。
   **倍数与跨度都从同一处算出来，页面里没有写死的数字**（第一版写死了 152，
   而面板算的是 185，两个数在同一屏上用了两种口径）。
2. **不判定**。高程着色是**显示刻度**，不是判定阈值。页面里没有「合格 / 不合格 /
   超标」这类字样，契约测试会核对，并配一个「注入『判定为合格』必须被认出来」的元测试。
3. **零外部资源**。三维渲染是内联手写 WebGL，没有 CDN、没有构建步骤、没有新依赖。
   这不是偏好 —— 契约测试里既有的「不得出现 `https?://` 外链」那一条把它定死了。

> ⚠ **Range 是自己实现的，不用 `FileResponse`**：宿主机 starlette 0.38.6 不支持 Range、
> 容器 0.41.3 支持，而 `requirements.txt` 只钉了 fastapi，**starlette 是浮动解析的**。
> 交给库就会出现「契约测试绿、线上行为不同」—— 与「宿主机全绿、容器里 500」同型。
> 不返回 206 的实现**视频照样能播，只是拖不动进度条**，「能播」会让粗看的人以为它对了。

### 三维起伏页的三处刻意的取舍（内容侧）

1. **车辆符号必须放大，倍数必须常驻显示**。鸟瞰下这条路只占约 1000 px，
   按真实尺寸画一辆 4.6 m 的车只有 **0.44 px** —— 等于没画。
   所以有放大滑块（默认 60×），并且**当前倍数写在读数区里**。
   符号的 `z` 取自**网格**而不是 CSV 的 `chassis_z_m`：后者是质心高度，
   直接拿去当符号高度会让车浮在路面上方。
2. **「没有数据」与「实测 0」必须不同色**。沿程量可以看成 0，也可以看成
   「这段没有数据」。轮荷实测**两者都真实存在**（13077 个顶点里 45 个无数据，
   有数据的顶点里确实有 0 值）—— 一个表示「没测」的零和一个实测出来的零
   共用一种颜色，读者会把前者当成后者。无数据走**条纹**，且不参与色带。
3. **缺位姿时报告，不画在原点**。CSV 少了 `x_m / y_m / s_m / heading_deg`
   里的任何一列，页面就**明确报缺位姿**、什么都不画。
   把缺失默认成 `(0,0)` 会画出一张看起来正常、实际全错的图 —— 那比报错更坏。
   契约测试**逐列各删一次**：单删一列时 `and`/`or` 写错仍然会通过，只有逐列才暴露。

### 坐标基准面板的两处刻意的取舍

1. **`ready` 与 `assumed` 分开显示**。前者是「这个基准能不能用」，
   后者是「这个基准值可不可信」。当前 `ready: false`（不参与任何几何计算）、
   `assumed: true`（带号是从数据反推的，未经设计方确认）。合并成一个标记，
   就等于把「暂时不能用」和「用了但可能错」说成同一件事。
2. **确认前不填 EPSG**。带号 39 推出来了，但 EPSG 编码是**由带号派生的**，
   凭记忆填一个等于把一个猜测伪装成查证过的事实。页面显示推断依据
   （六条，逐条列出）与确认路径，`epsg_after_confirm` 留空。

> ⚠ **`crs.yaml` 的路径按模块所在目录解析，不按进程 CWD**。
> 原先写的是 `pathlib.Path("config/crs.yaml")` —— 那意味着「只有从对的目录启动
> 才读得到」，而读不到时的表现是接口照常 200、页面带号那一栏静静地空着。
> 本 feature 实测踩过一次：契约测试从 `scaffold/tests/contract/` 跑，
> 于是 `/v1/sim/manifest` 的 `geographic_frame` 恒为空。
> 这类失败不报错，只少显示东西。

> ⚠ **`/v1/sim/manifest` 返回 `{manifest, crs}`，不是扁平的清单**。
> 磁盘上的 `manifest.json` 是扁平的，很容易顺手 `return JSONResponse(manifest)`。
> 页面是 `const { manifest, crs } = await resp.json()` —— 形状一改，
> 页面 destructure 出 `undefined`，表现为「载入失败」，而所有断字面量的测试照样绿。
> 现在契约测试直接钉住顶层键集合。

### 空表页的两处刻意的取舍

1. **次序不自作主张**。页面直接展示 `/v1/catalog/gaps` 给的次序，**不自己再排一遍** ——
   再排一遍就会出现「页面看到的」与「接口声称的」不一致，复核者拿 `priority_keys`
   复算时对不上，排序就不可证伪了。
2. **归因坏了不拖垮整页**。归因的依赖链比盘点长一跳（多经 M2）：
   取不到时降级为「只列空表、不显示空因」，但**必须把降级说出来**
   （页面上写着「这不是『这些表没有空因』」）。不说，读者就会把那 26 行
   理解成「这些表本来就没原因」。

> `/v1/modules/status` 会**实测**每个模块，把登记状态与实测结果并排显示。
> 刻意不缓存「上次健康」——集成面骗人就失去意义了。
> 同一条道理适用于缺口归因：**每次请求现取**，不缓存（见 `test_gap_attribution.py` 第 9 组）。

## 六、别踩的坑（本项目已经踩过的）

1. **不要拿合成数据当验证依据**。造数器只注入有限的违约类型，且其中一类
   （`axle_num` 不符）因造数器自身的 bug 从未真正产生过——拿它「验证通过」会得到假结论。
2. **未标定的阈值不得用于生产判定**。凡有阈值的配置项都标了 `calibrated: false`，
   门禁据此拒绝出结论（返回 503 而不是「通过」）。
3. **不要在双引号字符串里夹中文引号**（`"…"…"`）——Python 与 YAML 都会报错，本项目已踩两次。
4. **容器内监听端口统一 8000**，宿主端口由 compose 的 `ports:` 决定，两者别搞混。
5. **compose 的 `volumes:` 相对路径是相对 compose 文件所在目录解析的**，不是相对仓库根。
   写成 `./artifacts/sim` 会指向 `scaffold/artifacts/sim` —— 一个 docker **顺手建出来的
   空目录**。表现是页面 503「清单不存在」，而宿主机上产物明明都在，很容易去查路由
   或挂载权限，查不到点子上。本 feature 实测踩过一次，正确写法是 `../artifacts/sim`。
   契约测试现在**不比对字符串**，而是按 compose 的规则把路径解析出来再看磁盘。
6. **`rm -f` 不是只读测试**。它对不存在的文件也返回 0，所以「容器里 `rm -f` 交付目录
   的文件返回 0」什么也证明不了。只有 `touch` / `mkdir` 才是。本 feature 实测踩过一次。
7. **新增页面必须同时做四件事**：写 `xxx.html`、加路由、`Dockerfile` 里 `COPY`、
   `test_console.py` 的 `PAGES` 里登记。**缺任何一件的表现都是「宿主机测试全绿、
   容器里 500」**，因为契约测试读的是仓库里的文件，不是镜像里的。已踩过一次，
   现在由 `PAGES` 清单 + Dockerfile COPY 清单两个守卫钉住。
8. **`if status == 200:` 包住断言 = 空转**。本 feature 里 `/v1/sim/manifest` 的
   三条断言原先被这样一个 `if` 包着，而接口当时正因为路径问题返回 503 ——
   三条断言**一条都没跑**，汇总照样打印「全部通过」。写测试时把 `200` 本身
   也断言掉（`ok("接口可达", r.status_code == 200)`），再进 `if`。
9. **桩要模拟接口的形状，不是文件的形状**。验收页面时我写了个无浏览器的
   Node 桩，直接把 `manifest.json` 喂给页面 —— 页面 destructure 出 `undefined`
   报「载入失败」，我差点去改一个**本来正确**的页面（接口返回的是 `{manifest, crs}`）。
   **桩错了会伪装成被测对象的 bug**，而且伪装得很像。
10. **`node --check` 只证明能解析，不证明算得对**。本会话没有浏览器、没有图像输入，
   所以验收是三层：`node --check`（语法）→ 把页面**自己的函数**拿真实产物在 Node 里
   跑一遍并断言数值（31 条：解网格、算曲率、按里程取轮荷、投影）→ HTTP 层八条判据。
   中间那层才是真正能发现算错的。**只做第一层和第三层，页面可以是「能解析、
   接口通、但一打开就报错」的。**
11. **剥掉 `env` 比不剥更危险**。八条判据的探针第一次只给子进程 `PATH=/usr/bin:/bin`，
   运行器里的 `uv` 找不到，19 个套件全「失败」—— 看起来完全像代码坏了。
   子进程要么透传真实环境，要么明确知道自己在省什么。
