## 五、页面与取数口径

| 页面 | 路径 | 取数 |
|---|---|---|
| 首页 | `/` | `/gw/v1/modules/status` |
| 表盘点 · 缺口归因 | `/tables` | `/gw/v1/catalog/tables` ＋ `/gw/v1/catalog/gaps` |
| 几何查询 | `/geometry` | `/gw/v1/geometry/*` |
| 三维起伏 | `/sim` | **不走 `/gw`**：交付目录 `artifacts/sim/`（只读挂载） |
| 设计导入 | `/import` | 写走 **自己的端点**，不借 `/gw`（`/gw` 是只读的） |

**页面一律经 `/gw` 取数，M9 永不直连数据库**（三条硬线之「读只经 M3 rpdao」）。
`/gw` 只转发 `v1/` 前缀下的 GET，且**只读** —— 一个无限制的转发器等于把 M9 变成任意 URL 抓手。

**唯一例外是 `/sim`**：它读的是**本模块自己的交付资产**（路面网格，从库中数据离线再生），
不是别人的业务数据，所以既不经 `/gw`、也不碰数据库 —— 它读文件。
`/artifacts/{name}` 是**白名单路由**：只认清单 `manifest.json` 里登记且 `present: true`
的名字。目录里存在但未登记的文件取不到，路径穿越在查表这一步就失败了，
**根本没有机会拼路径**。

### 三维起伏页的三处刻意的取舍

1. **垂直放大默认真尺度，且倍数常驻显示**。这条路平面约 5.5 km、高差 29.75 m
   （1:185），真尺度下画面几乎是平的。默认放大更好看，但一张截图拿出去就会被
   当成真实纵坡 —— 所以默认 1.0，并把「这是尺度的性质，不是数据的问题」写在页面上。
   **倍数与跨度都从同一处算出来，页面里没有写死的数字**（第一版写死了 152，
   而面板算的是 185，两个数在同一屏上用了两种口径）。
2. **不判定**。高程着色是**显示刻度**，不是判定阈值。页面里没有「合格 / 不合格 /
   超标」这类字样，契约测试会核对，并配一个「注入『判定为合格』必须被认出来」的元测试。
3. **零外部资源**。三维渲染是内联手写 WebGL，没有 CDN、没有构建步骤、没有新依赖。
   这不是偏好 —— 契约测试里既有的「不得出现 `https?://` 外链」那一条把它定死了。

> ⚠ **Range 是自己实现的，不用 `FileResponse`**：宿主机 starlette 0.38.6 不支持 Range、
> 容器 0.41.3 支持，而 `requirements.txt` 只钉了 fastapi，**starlette 是浮动解析的**。
> 交给库就会出现「契约测试绿、线上行为不同」—— 与「宿主机全绿、容器里 500」同型。
> 不返回 206 的实现**视频照样能播，只是拖不动进度条**，「能播」会让粗看的人以为它对了。

### 空表页的两处刻意的取舍

1. **次序不自作主张**。页面直接展示 `/v1/catalog/gaps` 给的次序，**不自己再排一遍** ——
   再排一遍就会出现「页面看到的」与「接口声称的」不一致，复核者拿 `priority_keys`
   复算时对不上，排序就不可证伪了。
2. **归因坏了不拖垮整页**。归因的依赖链比盘点长一跳（多经 M2）：
   取不到时降级为「只列空表、不显示空因」，但**必须把降级说出来**
   （页面上写着「这不是『这些表没有空因』」）。不说，读者就会把那 26 行
   理解成「这些表本来就没原因」。

> `/v1/modules/status` 会**实测**每个模块，把登记状态与实测结果并排显示。
> 刻意不缓存「上次健康」——集成面骗人就失去意义了。
> 同一条道理适用于缺口归因：**每次请求现取**，不缓存（见 `test_gap_attribution.py` 第 9 组）。

## 六、别踩的坑（本项目已经踩过的）

1. **不要拿合成数据当验证依据**。造数器只注入有限的违约类型，且其中一类
   （`axle_num` 不符）因造数器自身的 bug 从未真正产生过——拿它「验证通过」会得到假结论。
2. **未标定的阈值不得用于生产判定**。凡有阈值的配置项都标了 `calibrated: false`，
   门禁据此拒绝出结论（返回 503 而不是「通过」）。
3. **不要在双引号字符串里夹中文引号**（`"…"…"`）——Python 与 YAML 都会报错，本项目已踩两次。
4. **容器内监听端口统一 8000**，宿主端口由 compose 的 `ports:` 决定，两者别搞混。
5. **compose 的 `volumes:` 相对路径是相对 compose 文件所在目录解析的**，不是相对仓库根。
   写成 `./artifacts/sim` 会指向 `scaffold/artifacts/sim` —— 一个 docker **顺手建出来的
   空目录**。表现是页面 503「清单不存在」，而宿主机上产物明明都在，很容易去查路由
   或挂载权限，查不到点子上。本 feature 实测踩过一次，正确写法是 `../artifacts/sim`。
   契约测试现在**不比对字符串**，而是按 compose 的规则把路径解析出来再看磁盘。
6. **`rm -f` 不是只读测试**。它对不存在的文件也返回 0，所以「容器里 `rm -f` 交付目录
   的文件返回 0」什么也证明不了。只有 `touch` / `mkdir` 才是。本 feature 实测踩过一次。
7. **新增页面必须同时做四件事**：写 `xxx.html`、加路由、`Dockerfile` 里 `COPY`、
   `test_console.py` 的 `PAGES` 里登记。**缺任何一件的表现都是「宿主机测试全绿、
   容器里 500」**，因为契约测试读的是仓库里的文件，不是镜像里的。已踩过一次，
   现在由 `PAGES` 清单 + Dockerfile COPY 清单两个守卫钉住。
