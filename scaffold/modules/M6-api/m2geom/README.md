# m2geom —— 这是**副本**，而且**不是容器用的那一份**

接手者看到两个同名文件时的第一个问题是「哪个是真的」。这个文件就是答案。

## 两句话

1. **真源是 `modules/M2-ingest/adapters/geom.py`**（和同目录的 `errors.py`）。
   本目录里的两个 `.py` 是它的**逐字节副本**。
2. ★★ **容器不用这一份。** 镜像里的 `/app/m2geom` 由 `Dockerfile` 第 39–41 行
   **从 M2 重新生成**（`COPY modules/M2-ingest/adapters/*.py` + 一个 printf 出来的空
   `__init__.py`）。

⇒ **改这里的 `geom.py` 不会改变容器里跑的任何东西。**
它只影响**宿主机上跑的契约测试**（测试把本目录加进 `sys.path`）。
两个消费者、两个来源 —— 这正是需要一条守卫的理由。

## 谁在守它

`tests/contract/test_region_frame.py` 的 **§1**：
拿本目录的 `geom.py` / `errors.py` 与 `M2-ingest/adapters/` 的原件逐个比 sha256，
**不一致就红**。所以上面那条"两个来源"不会悄悄分叉。

## ★ 为什么这个说明不能写成 `geom.py` 里的注释

因为**加一行注释就会破坏本文件正在解释的那条相等** ——
sha256 守卫立刻变红。

★ 这是个值得记住的形状：**当守卫就是"逐字节相等"时，
困惑发生的地方（副本文件本身）恰恰是禁止写说明的地方。**
所以说明只能放在旁边（本文件），放在 `__init__.py` 里也不行 ——
那一个被测试要求**必须为空**（M2 的 `__init__.py` 会 `from . import base, errors, weidi`，
把 19 个纬地解析器一起拖进来，复制它等于把坑一起搬过来）。

## 为什么当初要复制，而不是直接 import

见 `Dockerfile` 第 28–41 行的完整理由。一句话：
`M2-ingest/adapters/__init__.py` 会把 19 个解析器一起拉进来，
而它们要读文件系统、带 GBK 解码假设 —— M6 一个都不需要。
复制那两个文件、配一个空 `__init__.py`，可以让 M2 **一个字节都不用改**。
