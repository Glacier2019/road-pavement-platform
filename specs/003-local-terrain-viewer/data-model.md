# Phase 1 Data Model: 局部帧三维起伏查看器

本 feature **不新增任何数据库表**。这里定义的"数据"全部是**文件产物**，
它们的形状由 `contracts/` 下的新契约约束。

---

## 1. 交付目录（Artifact Directory）

仓库内固定路径：`artifacts/sim/`。容器内以**只读**方式挂在 `/data/sim`。

### 目录内容

| 文件 | 类型 | 大小量级 | 必需 |
|---|---|---|---|
| `manifest.json` | 清单（契约实例） | ~2 KB | **是** |
| `terrain_overview.bin` | 抽稀网格，u 步长 4.0 m | ~289 KB | **是** |
| `terrain_near.bin` | 抽稀网格，u 步长 1.0 m | ~1,157 KB | 否 |
| `wheel_loads.csv` | 车辆轨迹（含平面位姿） | ~800 KB | 否 |
| `vehicle_on_crg_lane_right_10x.mp4` | 仿真视频，10 倍速 | ~11 MB | 否 |
| `vehicle_on_crg_lane_right_realtime.mp4` | 仿真视频，实时 | ~28 MB | 否 |

★ **清单是必需项，其余按可用性降级。** 一个只有清单和总览网格的交付目录，
页面仍然可用（看得到起伏，只是没有车辆和视频）。

### 不变量

- 目录内**每一个**可被 `GET /artifacts/{name}` 取到的文件，
  **必须**在 `manifest.json` 的 `artifacts[]` 里有一条记录。
- 反向不强制：清单一律允许登记尚未产出的文件，但必须标 `present: false`。
  ★ 理由：清单是**契约**，它先于产物存在。逼着清单只能描述已存在的东西，
  会让"先定契约再产出"变成"先产出再补契约"。
- 容器对该目录**只读**。任何写入尝试都应失败（结构上做不到）。

## 2. 抽稀网格（Decimated Terrain Mesh）

这是本 feature 新增的**核心数据结构**。

### 二进制布局（`terrain_*.bin`）

小端序、无对齐填充、无自描述头部：

| 偏移 | 类型 | 长度 | 含义 |
|---|---|---|---|
| 0 | `Float32[]` | `nu * nv * 3` | 顶点位置，**局部米制坐标**（X=北, Y=东, Z=上） |
| `nu*nv*12` | `Uint16[]` | `(nu-1)*(nv-1)*6` | 三角面索引 |

★ **二进制里不放头部。** 全部元信息（`nu`、`nv`、`dtype`、字节偏移）写在
`manifest.json` 里。理由：二进制保持"哑数组"，契约集中在一个人能读的地方。

★ **索引必须是 `Uint16`。** 见 `research.md` R2：四档抽稀的顶点数全部低于 65,536。
**这一点必须由抽稀脚本断言**，而不是靠巧合 —— 顶点数一旦越过该界限，
`Uint16` 会静默截断，几何会以一种"看起来只是有点错"的方式坏掉。

### 横向样点（`nv = 9`）

| 序 | v (m) | 含义 |
|---|---|---|
| 0 | −4.250 | 左侧路面边缘 |
| 1 | −3.500 | 左侧车道边缘（硬路肩外缘） |
| 2 | −2.625 | 左侧行车道 + 硬路肩中点 |
| 3 | −1.750 | **左侧车道中心** |
| 4 | 0.000 | **路中线** |
| 5 | +1.750 | **右侧车道中心（仿真走的就是这条）** |
| 6 | +2.625 | 右侧行车道 + 硬路肩中点 |
| 7 | +3.500 | 右侧车道边缘 |
| 8 | +4.250 | 右侧路面边缘 |

★ 这 9 个样点不是均匀采样 —— 它们**落在有物理意义的 v 上**，
所以网格的边线就是路面边线、车道边线、车道中心线。
这让人一眼能看出"车在哪条车道"，而不需要额外的参考几何。

### 顶点坐标

`z` 取自 CRG 实测高程（不是中线控制点 z）。

★ **这一点有实测依据**：`05_vehicle_on_crg.cpp` 里的永久自检记录
「中线控制点 z 与地形实测最大差 200.09 mm」—— 中线控制点的 z
**比实际路面高约 0.2 m，且没有路拱**。用它当路面高程会得到一个
整体抬高、且平坦得不像路的曲面。

### 派生量（不存盘，页面内计算）

- **三角面法线**：由相邻顶点差分求得。
- **顶点色**：按当前选中的沿程量插值。
- **沿程里程 `s`**：由顶点在网格中的 u 序号反算。

## 3. 车辆轨迹（Vehicle Track）

即补充过平面位姿的 `wheel_loads.csv`。

### 表头

```csv
t_s,s_m,lat_m,speed_mps,chassis_z_m,x_m,y_m,heading_deg,a0_L_Fz_kN,...,a1_R_pz_m
```

**23 列** = 原有 21 列 + 追加的 3 列 —— 但注意 `x_m, y_m, heading_deg`
插在 `chassis_z_m` **之后**、轮荷列**之前**，以保持"时刻 → 位置 → 载荷"
的阅读顺序。

### 三列新字段

| 列 | 单位 | 含义 | 来源 |
|---|---|---|---|
| `x_m` | m | 局部坐标北向分量 | `vehicle.GetPos().x()` |
| `y_m` | m | 局部坐标东向分量 | `vehicle.GetPos().y()` |
| `heading_deg` | 度 | 航向，从 +X（北）向 +Y（东）为正 | 由车辆朝向导出 |

★ **追加而非重排。** 已有列已被 `plot_wheel_loads.py` 消费，
重排会让它**静默读错列** —— 不报错，只是图变成错的。

### 与网格的关系

- 轨迹的 `z` **不使用** `chassis_z_m`（那是底盘，不是车轮接地点）。
  车辆符号贴在**网格表面**上，由网格查得高度。
- 轨迹的 `x_m / y_m` 与网格顶点**必须处在同一个坐标系**。
  ★ 这是 spec 的 Edge Case「轨迹与路面来自不同批次」要防的情形：
  若不一致，车辆会整体错位。**页面必须能发现并提示**，
  判据是"车辆的平面位置是否始终落在网格的平面外接矩形内"。

## 4. 坐标基准配置（CRS Config）

`scaffold/modules/M9-console/config/crs.yaml`

```yaml
# 当前使用的坐标基准。局部帧不需要它；它的存在是为区域帧预留挂点，
# 并让"39 带"这个推断值有一个带标记的位置，而不是散落在对话记录里。
local_frame:
  axes: X=北, Y=东, Z=上     # 设计坐标系，与大地基准无关
  unit: m

geographic_frame:
  ready: false               # 区域帧未就绪
  ellipsoid: CGCS2000
  projection: 高斯-克吕格
  zone_width_deg: 3
  zone_number: 39
  central_meridian_deg: 117
  assumed: true              # ★ 推断值，未经设计人确认
  evidence:
    - Y 值无带号前缀（534559..537679，带前缀应约 39534559）
    - Y 东偏 34.6..37.7 km，对应 39 带落点为闽中山区
    - 40 带落点为台湾海峡，排除
    - 投影变形 14.75..17.51 mm/km，满足规范 25 mm/km
```

### 字段语义

| 字段 | 类型 | 语义 |
|---|---|---|
| `ready` | bool | 区域帧能否使用。**当前 `false`** —— 因为带号未经确认 |
| `assumed` | bool | 该基准是推断值。**界面或日志必须能读到它** |
| `evidence` | list | 推断依据。**与值一同记录**，使接手者能复核或推翻 |

★ `ready: false` 与 `assumed: true` **是两个不同的标记**，不能合并：
一个说"能不能用"，一个说"值可不可信"。把 `ready` 设成 `true` 而
`assumed` 仍是 `true` 是合法状态 —— 那是"先用着，但我知道它是猜的"。

## 5. 关键实体关系

```text
交付目录 1 ── 1 清单（契约实例）
     │
     ├── 1..2 抽稀网格  ──→ 页面渲染三维路面
     ├── 0..1 车辆轨迹  ──→ 页面叠车辆符号
     └── 0..2 仿真视频  ──→ 页面嵌播放器

坐标基准配置 ──→ 仅被局部帧读取以显示"当前基准"，
                 不参与任何几何计算（局部帧不需要它）
```

★ **最后一条是本数据模型最重要的性质**：
坐标基准配置与三维几何之间**没有数据依赖**。
这就是"这条路本身的三维起伏不需要带号"在数据结构上的体现。
