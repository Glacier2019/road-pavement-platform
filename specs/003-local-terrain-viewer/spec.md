# Feature Specification: 局部帧三维起伏查看器

**Feature Branch**: `003-local-terrain-viewer`

**Created**: 2026-10-10

**Status**: Draft

**Input**: User description: "这条路本身的三维起伏是必须的 / 3 度带 39 带，中央子午线 117°E，
CGCS2000；落点约 25.08°N / 117.34°E（闽中山区）/ 起 speckit-specify，范围锁定：
局部帧三维起伏查看器（M9 新增页 + 产物搬到交付目录 + 只读挂载）；仿真 CSV 补
x_m, y_m, heading_deg（鸟瞰与三维都要用）；带号配置项（默认 39 带，assumed: true，
界面或日志里显式标注）"

---

## 背景：为什么是"局部帧"，以及为什么不需要带号

本平台已经有 0.1 m 分辨率的路面高程数据，它在**设计坐标系**里，
是一个局部米制坐标系（X=北、Y=东、Z=上），**不依赖任何大地基准**。
所以「这条路本身的三维起伏」可以在完全不知道带号的情况下做出来。

反过来，一旦要把它放到地球上（区域路网、底图、DEM），就必须有带号。
带号现在**不在任何一处**：纬地 `.PRJ` 是 HintCAD 二进制、两次独立解码零中文；
`monitor_cross_section.lat/lon` 两行全空；全仓检索只找到投影**方法**
（高斯-克吕格 / CGCS2000），没有**带号**。

**本 spec 只做第一件事。** 区域帧另开 spec，且必须等带号从"推断"变成"确认"。

### 已有数据（实库实测，不是规划）

```limits
CRG u 范围 | 0.000 / 5805.400 | m
CRG v 范围 | -4.2500 / 4.2500 | m
网格步长 | 0.1 / 0.1 | m
v 通道数 | 86 / 86 | 个
高程范围 | 54.0641 / 83.8141 | m
最大曲率 | 0.0039 / 0.0039 | 1/m
```

```limits
线形单元 | 33 / 33 | 个
其中直线 | 9 / 33 | 个
其中缓和曲线 | 16 / 33 | 个
其中圆曲线 | 8 / 33 | 个
圆曲线半径 | 255 / 500 | m
起终点高差 | 29.75 / 1 | m
平面外接矩形 | 4521 / 3120 | m
```

**平面 4521 m 对高差 29.75 m = 1:152。** 这条事实决定了本 feature 的
核心交互设计（见 US1 的"垂直放大"）。

### 仿真产出的现状（实测）

```kv
轮荷 CSV 列数: 21 列
已有: t_s, s_m, lat_m, speed_mps, chassis_z_m + 16 个轮荷列
缺少: x_m, y_m, heading_deg
```

程序里 `vehicle.GetPos()` 是现成的（`chassis_z_m` 就是取它的 `.z()`），
只是没有写进 CSV。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看见这条路本身的三维起伏 (Priority: P1)

用户打开一个页面，看见这条路的三维形状：它怎么弯、哪里高、哪里低、
纵坡在哪一段最陡。可以旋转、缩放、平移，从任意角度看。

**Why this priority**: 这是用户明确要求"必须"的一件事，也是全平台唯一
一个把路面高程数据当作**几何**而不是**数字**来用的视图。它不依赖仿真、
不依赖带号、不依赖任何外部服务，是三个故事里唯一可以单独交付的。

**Independent Test**: 只看这个页面就能判断路线形状是否正确 ——
能指出全程最高点与最低点的大致位置，能数出几个明显的弯，
能看出纵坡的方向变化。不需要仿真数据在场。

**Acceptance Scenarios**:

1. **Given** 路面的高程网格已就位，**When** 用户打开该页面，
   **Then** 页面显示一条连续的三维路面带，其平面走向与线形数据一致，
   其高程变化与高程数据一致。
2. **Given** 页面已显示路面，**When** 用户旋转视角，
   **Then** 画面连续更新且不出现几何断裂、翻面或空洞。
3. **Given** 页面显示的是真尺度几何，**When** 用户查看任意一段，
   **Then** 界面**显式给出当前的垂直放大系数**，
   且用户可以把该系数调回 1（真尺度）。
4. **Given** 用户把垂直放大调回 1，**When** 他观察画面，
   **Then** 起伏肉眼几乎不可见 —— 这个现象本身是正确的，
   且界面不因此自动改变系数。

---

### User Story 2 - 看见车在这条路上走 (Priority: P1)

用户把一次仿真回放叠在三维路面上，看见车辆沿路行驶的轨迹，
并能看出它在某个桩号处的横向位置（在右侧车道）。

**Why this priority**: 用户先前明确要求"要显示车辆，这样能看到轨迹"，
且本 feature 的用途之一就是让仿真结果可被审阅。它依赖 US1 的几何，
但依赖关系是单向的：US1 不需要 US2 就能交付。

**Independent Test**: 给定一次已完成的仿真产出，页面能把车辆符号
放到路面上正确的位置，且位置随回放推进而移动。
可用"车辆始终落在路面范围内"这一条独立判断。

**Acceptance Scenarios**:

1. **Given** 一次仿真已产出轨迹，**When** 用户播放回放，
   **Then** 车辆符号沿路面连续移动，位置与该时刻的里程一致。
2. **Given** 回放正在播放，**When** 用户暂停并查看车辆位置，
   **Then** 车辆的横向位置落在路面带之内，不出现"悬在路外"。
3. **Given** 车辆真尺寸约 2 m 宽，**When** 视图覆盖全程，
   **Then** 界面**不假装**车辆可见 —— 它必须以可辨识的符号呈现，
   且该符号的放大倍数可见。
4. **Given** 轨迹数据缺少平面位姿，**When** 用户尝试回放，
   **Then** 页面给出明确提示而不是静默失败或猜测位置。

---

### User Story 3 - 看见数据沿着路分布 (Priority: P2)

用户把某个沿程量（例如轮荷、高程、曲率）按桩号染到路面上，
一眼看出它在哪一段异常。

**Why this priority**: 这是"数智化"三个字的落点 ——
把几何视图变成数据视图。但它依赖 US1 与 US2，且没有它本 feature 仍可用。

**Independent Test**: 换一个沿程量，同一段路面颜色随之改变；
同一个颜色对应同一个数值区间。

**Acceptance Scenarios**:

1. **Given** 一个沿程量与它的桩号，**When** 用户选择它，
   **Then** 路面按该量的数值区间着色，并显示色标。
2. **Given** 已着色，**When** 用户把鼠标移到路面某处，
   **Then** 显示该处的桩号与该量的数值。
3. **Given** 某个桩号区间没有数据，**When** 它被着色，
   **Then** 该区间以"无数据"的样式呈现，**不与数值 0 混用同一种颜色**。

---

### User Story 4 - 仿真产物从一个稳定的交付目录提供 (Priority: P2)

用户或学生组拿到的是平台里一个**固定的**目录，里面是完整的仿真产物
（视频、轨迹、图），而不是某次调试留在沙箱里的临时文件。

**Why this priority**: 目前产物躺在沙箱临时目录里，那个目录随时会被清掉，
而且它不是契约的一部分。把它变成交付目录是让这个 feature 可交接的前提。

**Independent Test**: 清掉沙箱临时目录后，交付目录内容与页面功能不受影响。

**Acceptance Scenarios**:

1. **Given** 仿真已完成，**When** 产物被交付，
   **Then** 它们位于一个仓库内固定的交付目录，路径可写进文档。
2. **Given** 交付目录已存在，**When** 平台容器启动，
   **Then** 它能**只读**访问该目录，且不修改其中任何文件。
3. **Given** 交付目录为空或缺失，**When** 用户打开相关页面，
   **Then** 页面给出明确提示，且平台其余部分不受影响。

---

### User Story 5 - 带号是一个可以被看见的假定 (Priority: P3)

用户或接手的学生组在任何地方看到"当前使用 39 带"时，
同时看到它是**推断值**，以及它是由什么推出来的。

**Why this priority**: 它现在不影响任何已交付功能（局部帧不需要带号），
但它决定将来一旦要放上地球，别人会不会把它当成事实。

**Independent Test**: 改配置里的带号，能在日志或界面上看到不同的值；
不改配置，能看到 `assumed` 标记。

**Acceptance Scenarios**:

1. **Given** 默认配置，**When** 任何人查看当前的坐标基准，
   **Then** 同时看到"39 带 / 中央子午线 117°E / CGCS2000"
   与"推断，未经设计人确认"两项信息。
2. **Given** 带号被改成正确值，**When** 配置被更新，
   **Then** 不需要改动任何其它代码。

---

### Edge Cases

- **路面之外没有几何**：数据只覆盖 ±4.25 m。视图放大到路面之外时，
  必须显示"此处无数据"，而不是延伸出臆造的地面。
- **垂直放大被误读为真实纵坡**：任何一张导出的图或截图，
  若使用了非 1 的放大系数，必须把系数印在图上。
- **仿真轨迹与路面来自不同批次**：如果轨迹的桩号基准与路面的不一致，
  车辆会整体错位。页面必须能发现并提示这种不一致。
- **断链**：桩号在断链处会跳变。若将来引入断链数据，
  沿桩号的着色必须断开而不是插值跨越。
- **高差只有 29.75 m**：某些视角下画面会接近一张平面图 ——
  这是数据本身的性质，不是渲染错误。

## Requirements *(mandatory)*

### Functional Requirements

#### 路面三维几何（P1）

- **FR-001**: 系统 MUST 由路面高程数据生成连续的三维路面几何，
  其平面走向与线形数据一致，高程与高程数据一致。
- **FR-002**: 系统 MUST 支持旋转、缩放、平移，且交互连续无几何断裂。
- **FR-003**: 系统 MUST 提供一个可调**垂直放大系数**，
  且该系数在界面上**始终可见**；真尺度（系数 1）可取。
- **FR-004**: 系统 MUST NOT 因画面"看起来太扁"而自动施加未声明的放大。

#### 仿真回放（P1）

- **FR-005**: 仿真产物 MUST 记录车辆在每一采样时刻的平面位姿
  （X、Y 与航向），与既有列一并写出。
- **FR-006**: 系统 MUST 能按时间回放轨迹，并把车辆符号放在路面上
  与该时刻里程一致的位置。
- **FR-007**: 车辆符号 MUST 可辨识；其非真实尺度 MUST 在界面上可见。
- **FR-008**: 当轨迹缺少平面位姿或与路面基准不一致时，
  系统 MUST 明确报告，而非猜测位置。

#### 沿程数据着色（P2）

- **FR-009**: 系统 MUST 支持按桩号把一个沿程量的数值区间映射到路面颜色，
  并显示色标。
- **FR-010**: 系统 MUST 能查询路面上任一点的桩号与该点数值。
- **FR-011**: 无数据的区段 MUST 与数值 0 使用不同的视觉编码。

#### 交付与部署（P2）

- **FR-012**: 仿真产物 MUST 位于仓库内一个固定的交付目录，
  且该路径 MUST 被记录在文档中。
- **FR-013**: 平台容器 MUST 以**只读**方式访问该交付目录。
- **FR-014**: 交付目录缺失或为空时，相关页面 MUST 给出明确提示，
  且不影响平台其它功能。
- **FR-015**: 交付目录 MUST NOT 位于任何沙箱临时目录之下。

#### 坐标基准（P3）

- **FR-016**: 当前使用的带号与中央子午线 MUST 是**可配置项**，
  MUST NOT 硬编码在逻辑中。
- **FR-017**: 配置 MUST 携带一个"该值是推断值"的标记，
  且该标记 MUST 在界面上或日志中可见。
- **FR-018**: 推断所依据的证据 MUST 与配置一同记录，
  使接手者能复核或推翻它。

### Key Entities

- **路面高程网格**：局部米制坐标系下的规则网格，含平面位置与高程。
  已有实现产物。
- **车辆轨迹**：一次仿真的时序记录，含时刻、里程、横向偏移、
  平面位姿与轮荷。
- **交付目录**：仓库内固定路径，存放仿真产物，平台只读访问。
- **坐标基准配置**：带号、中央子午线、椭球，以及"推断"标记与依据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 打开页面到看见路面三维几何，无需任何额外命令行操作。
- **SC-002**: 从页面画面能正确指出全程最高点与最低点所在的桩号
  区间（与数据一致）。
- **SC-003**: 车辆在整个回放过程中，其平面位置始终落在路面带之内。
- **SC-004**: 给定任一沿程量，换量后色标与颜色对应关系随之更新，
  不需要改动代码。
- **SC-005**: 清空沙箱临时目录后，交付目录内容与页面功能均不受影响。
- **SC-006**: 交付目录在整个使用过程中零写入。
- **SC-007**: 任何一张含垂直放大的导出图中，放大系数均可读到。
- **SC-008**: 查看坐标基准时，能同时读到带号与"推断"标记。

## Assumptions

- 局部米制坐标系（X=北、Y=东、Z=上）足以表达全部所需几何；
  本 feature **不做**任何大地坐标转换。
- 路面高程网格的精度（0.1 m）足以支撑本 feature 的用途；
  本 feature 不重新生成高程数据。
- 仿真在平台之外运行并产出文件；本 feature 不负责调度仿真。
- 垂直放大是**显示选项**，不改变任何存储的数值。
- 交付目录的内容由仿真方写入，平台侧只读。
- 带号推断的证据（东偏量、合规性、地形特征）已在本次会话中记录；
  本 feature 只负责把它变成显式配置，不负责确认它。

## 依赖与风险

- **依赖**：路面高程网格已存在且可用（已实测）。
- **依赖**：仿真需重跑一次以产生平面位姿列；这是本 feature 内唯一
  需要重新执行仿真动作的地方。
- **风险（高）**：带号若被推翻，区域帧的全部设计需要重做。
  缓解：本 spec 明确把区域帧排除在外。
- **风险（中）**：垂直放大可能被误读为真实纵坡，导致对坡度作出错误判断。
  缓解：FR-003/FR-004 与 SC-007 强制任何非真尺度都可见。
- **风险（中）**：交付目录一旦成为契约，误写入会破坏可复现性。
  缓解：FR-013/FR-015 与 SC-006。
- **风险（低）**：路面只有 ±4.25 m 宽，视图放大到路外会显得"空"。
  缓解：Edge Cases 明确要求显示"此处无数据"。
