## E1. 坐标基准（`CrsBinding`）—— 新增的实体，两级各挂一份

### 组成字段（两处一模一样）★ 2026-10-12 按宪法原则 VI 重新定权

| 字段 | 类型 | 可空 | 权威性 | 说明 |
|---|---|---|---|---|
| **`crs_epsg`** | `integer` | ✅ | ★★★ **权威字段** | SRID。有基准时 MUST 非空，且能在 `spatial_ref_sys.srid` 里查到 |
| `crs_zone_number` | `smallint` | ✅ | 可空注释 | 带号。**只在有「带」这个概念的投影族里才有意义** |
| `crs_central_meridian_deg` | `numeric(9,6)` | ✅ | 可空注释 | 中央子午线。手写换算路径需要它 |
| `crs_zone_width_deg` | `numeric(4,2)` | ✅ | 可空注释 | 带宽。同理只在分带族里有意义 |
| `crs_assumed` | `boolean` | ✅ | ★ 见 E4 | 「能不能用」与「值可不可信」是两问 |
| `crs_evidence` | `text` | ✅ | ★ 推断依据 | **MUST 与基准同存**（FR-015） |

### ★★★ 为什么权威字段是 SRID，而不是「带号 + 中央子午线」

**因为另外三个只在一种投影族里说得通。**

| 投影族 | 有「带号」吗 | 有「中央子午线」吗 |
|---|---|---|
| 中国高斯-克吕格 3 度带 | 有 | 有 |
| UTM | 有（另一套编号） | 有 |
| **Lambert 等角圆锥**（如 2154） | ★ **没有** | 有（但不是分带的产物） |
| **阿尔伯斯等积**（如 5070） | ★ **没有** | 有（同上） |
| 地理坐标（如 4326） | 没有 | 没有 |

⇒ ★★ **把带号做成必填字段，就是把数据模型钉死在中国高斯-克吕格上** —— 而这是产品要卖到国外时第一个要拆掉的东西（宪法原则 VI）。

★★ 实测：全表 **8500** 个 SRID，`proj4text` 里有 `+lon_0` 的只有 **5818** 个（**UTM 全部没有**）。所以连「从登记表抓中央子午线」都**不能**当通用来源（research.md R11 补记）。

### 那三个注释字段留着干什么

★ **两个用处，都不是「表达基准」**：

1. **人类要读的那个** —— 工程上说的是「117 带」，不是「4548」。★ 但它是**注释**，不是真源。
2. **手写换算路径的输入** —— 第一层换算（快、离线）需要中央子午线。★ 它需要，不改变它是派生的。

★★ **反过来说：没有这三个字段，SRID 一样能算。** 实测「只给 SRID 不给中央子午线」，4548 / 32650 / 2154 / 5070 全部成功。

### 挂在哪

| 级 | 表 | 现有行数 | 现有列数 |
|---|---|---|---|
| 项目级 | `design_project` | 1 | 11 |
| 路段级 | `road_section` | 2 | 13 |

★ 列名带 `crs_` 前缀，是为了将来一眼能 grep 出「所有和坐标基准有关的列」—— 实测过：现状下全库 grep `srid|epsg|crs|zone|meridian` **零个业务列命中**，加前缀后**命中即全部**。

### 分布（同一次查询里就位）

```
SECTIONS_SQL 现有：
  LEFT JOIN design_project p ON p.id = s.design_project_id    ← ★ 已经在
加列后：
  SELECT ..., s.crs_* AS section_crs_*, p.crs_* AS project_crs_* , ...
```

★ **不需要新 join、不需要新 DAO 方法**（research.md R3）。

## E2. 生效基准（`EffectiveCrs`）—— 派生值，不是新表

★★ **这是本 feature 的核心概念，也是最容易被实现成「取一个」的地方。**

两级都存在，所以「用哪个」不是选择题而是**一致性检查**（Q1b = B）。派生规则**逐字**如下：

| # | 项目级 | 路段级 | 生效值 | 来源级别 | 行为 |
|---|---|---|---|---|---|
| 1 | 有 | 有，**且相等** | 该值 | `project` | ✅ 通过 |
| 2 | 有 | 有，**不相等** | — | — | ★ **报错**，且错误信息 MUST 说出**两级的取值各是什么**（SC-009） |
| 3 | 有 | 没填 | 项目的 | `project` | ✅ 通过 |
| 4 | 没填（或路段无项目） | 有 | 路段的 | `section` | ✅ 通过（FR-010） |
| 5 | 没填 | 没填 | — | — | ★ **有类型的「没有」**（FR-003） |

### 第 4 条为什么必须通过，而不是报错

★★ **实测的：路段 1「滨海大通道试验段」`design_project_id = NULL`。**

如果第 4 条判为报错，那个路段就**永远无法定位**。那是把一条能用的数据锁死，而不是在防错。

★ 而且它在数据层**已经是被处理过的形状** —— `LEFT JOIN design_project` 本来就会给出 `project_id = NULL`（research.md R3）。第 4 条只是顺着这个形状走。

### 「来源级别」是溯源，不是优先级

★★ **取 (b) 之后，级别不决定谁赢 —— 它只回答「这个值从哪儿读到的」。** 所以 FR-002 要求报来源级别，不是因为「级联顺序」，而是因为人要知道**这个值是在哪一级被写下的**：这样当他要改它时，知道该去改哪一行。

★ 实现上，第 1 条与第 3 条的生效值相同，但**来源级别不同**（都是 `project`）—— ★★ **注意第 1 条与第 3 条来源级别都是 `project`**：路段级填了相同的值，也不改变「权威来源仍是项目级」这个事实。这正是「路段级是冗余校验」的直接推论。

## E3. 不变量（MUST 被机器强制）

### I1. ★★★ SRID 为权威，三个习惯记法是可空派生（2026-10-12 按宪法原则 VI 改写）

```
crs_epsg 是唯一权威字段：
    有基准时 MUST 非空，且 MUST 在 spatial_ref_sys.srid 里查得到（FR-005），查不到当场拒绝。

crs_zone_number / crs_central_meridian_deg / crs_zone_width_deg 是可空注释：
    三个都有值时  ⇒ 与 crs_epsg 所指的基准 MUST 自洽
    任一个缺值时  ⇒ ★ MUST NOT 因此报错
```

★ 「缺值不报错」不是宽容，是**正确**：UTM 与 Lambert 没有「带号」记法，Lambert/aea 的中央子午线也不是分带的产物（E1）。

#### ★★★ 自洽怎么判 —— **不得用算式，要用行为**

❌ **作废（2026-10-12）**：`crs_central_meridian_deg == crs_zone_number * 3`
　★ 那个 `3` 是**硬编码的常量**，而 `test_sim_track.py` 的守卫原话是「带号是配置项，**不是代码里的常量**」。
　★★ 实测否证：`4545` 的 `+lon_0` 是 108，3 度带那边 `36×3=108` 偶然对上；而 `4524` 按 6 度带规律算出来 48，**实际是 108**。
　★ 一个偶然对上、一个直接错 —— **两个「规律」都是我猜的**。

❌ **也作废**：从 `spatial_ref_sys.proj4text` 抓 `+lon_0`
　★★ 实测：全表 8500 个 SRID，有 `+lon_0` 的只有 **5818** 个，**UTM 全部没有**。

✅ **采用 —— 比对行为，不比对记法**：

```
把同一个点分别用两条路径换算：
    路径一：crs_epsg           → 权威路径
    路径二：crs_central_meridian_deg 加上已实现的投影 → 手写路径
两者结果 MUST 落在同一容差内。
```

★★★ **为什么这条对任何投影族都成立**：它不假设任何一族的分带约定，只要求**两条路径指向同一个地方**。
★ 实测先例：手写路径与 PostGIS（4548）在三个点上差 **9 µm**（research.md R11）。
★ 容差取 **1e-4 m**；**不许取 1e-9** —— 那是拿浮点噪声当判据。

★ 这一条把「I1 三者自洽」从一个**记法问题**变成了一个**可观测问题** —— 而记法问题正是上面两个作废方案各自翻车的地方。

### I2. `assumed` 与 `crs_evidence` 的配对（照抄 004 的智慧）

```
crs_assumed = false  ⇒  crs_evidence MUST 非空（说清「凭什么确认」）
crs_assumed = true   ⇒  crs_evidence MUST 非空（说清「凭什么猜」）
```
★ 004 的做法是 `assumed=false` 时要求 `epsg_after_confirm` 非空；这里改成**要求依据非空**，因为 005 没有「确认后的 EPSG」这个第二字段 —— `crs_epsg` 就是最终值。

### I3. ★★ 两级一致（Q1b = B 的强制点）

```
路段有基准 AND 其项目也有基准  ⇒  两级的 crs_epsg MUST 相等
```

★ 原文写的是「（zone, central_meridian, epsg）三者 MUST 全部相等」——**2026-10-12 收紧为只比 `crs_epsg`**（宪法原则 VI）：
另外两个是**可空注释**，拿可空字段做相等判据，会在「一级填了注释、另一级没填」时产生无意义的报错。**权威相等就够了。**
★ 若两级都填了注释，注释也 MUST 自洽（I1），但那条由 I1 独立强制，不必在这里重复。

★★ **强制点放在写入侧（DB 触发器 / M2 的写路径），不放在读路径。** 理由见 research.md R6：读路径拦会把「一条路段的坏数据」升级为「整个列表接口挂掉」；而 004 已经确立「如实报出比拒绝更有用」。

★ 读路径的义务是**如实报出两级的值与来源级别**，不是自己拦。

## E4. 「能不能用」与「值可不可信」仍是两问

004 立的规矩（`ready` 说能不能用，`assumed` 说值可不可信）**原样继承**：

| 情形 | 能不能用 | 值可不可信 |
|---|---|---|
| 两级都没配 | ❌ 不能 | — |
| 配了、`assumed = true` | ✅ 能算 | ⚠ **是推断的** |
| 配了、`assumed = false` | ✅ 能算 | ✅ 已确认 |
| 两级不一致 | ★ **拒绝**（见 I3） | — |

★ 所以「毕设」这个项目的基准要带上它今天的状态：`zone 39 / CM 117 / EPSG 4548 / assumed = false`，`crs_evidence` 非空。

★★ **005 与 004 在这一点上的差别：004 是「一个全局值，只有 can/cannot」；005 是「每个项目各有一个值，各自 can/cannot + assumed」。** ⇒ 平台可以同时持有「项目 A 已确认、项目 B 还是推断的」。

## E5. 有类型的「没有」—— 不是 `null`，是缺字段

★★ 004 已经确立的形状：`position_source` 三值枚举 + `unavailable_reason`，**`lat_deg` / `lon_deg` 直接省略，而不是给 `null`**。

005 的对应形状：

```
请求一个没有基准的路段
  → 响应里 MUST NOT 出现任何经纬度字段
  → 出现一个说明为什么没有的字段（内容形如「项目 2 与路段 8 都没有配坐标基准」）
  → MUST NOT 回落到 39 带，MUST NOT 回落到任何全局默认
```

★★ **这与 `offset_band` 是同一条教义的两处应用：一个空间问题的答案，要么是「值 + 它的性质」，要么是「有类型的没有」。**

★ 而且它有一处**与 004 不同的地方**：004 的「没有」是二分的（有几何 / 没几何）；005 的有五态（E2 的五条）。**五态必须穷尽** —— 判据 SC-005 查的就是这个。
