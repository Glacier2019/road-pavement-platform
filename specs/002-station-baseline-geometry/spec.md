# Feature Specification: 桩号基准解耦与逐桩线形生成

**Feature Branch**: `002-station-baseline-geometry`

**Created**: 2026-09-27

**Status**: Draft

**Input**: 用户描述：「桩号是基础，客观存在的，路段可能不是很确定，路段长度不定，另外不是所有路段加起来可以覆盖整条路线桩号」＋「需要」

**前置**：feature 001（空表缺口归因）已完成，`geometry_point` 判定为 `module_not_built · 该段写适配器`，是本 spec 的直接动因。

---

## 背景：为什么必须先动桩号

用户提出一个结构性观察，**实测证实了它**：

| 路段 | 桩号区间（km） | 桩号序列行数 |
|---|---|---|
| 1 滨海大通道试验段 | **4635.000 ~ 4654.701** | **0** |
| 6 毕设 | **0.000 ~ 5.805421** | **332** |

两个路段相差 **4635 km**，不可能共享同一个「全线桩号基准」；而当前 332 个桩号**全部只挂在 section 6 之下**，section 1 一个都没有。

现行外键方向把「客观基准」塞进了「局部划分」：

```
station_sequence.section_id  ->  road_section   （桩号挂在路段下）
road_section.line_id         ->  road_line
```

三个问题随之而来：

1. **路段不确定**：路段是管理划分，会调整；桩号是客观里程，不会变。把不变的挂在会变的下，是层次倒置。
2. **路段长度不定**：`road_section.length_m` 实测 19701.0 与 5805.4，但路段边界由人填（`start_station_text` 是文本），无约束。
3. **路段之并不覆盖整条路线**（用户明确指出）：桩号区间的**并集是全集**，路段的并集**允许有洞**。用路段去界定桩号，会丢掉洞里的桩号。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 桩号脱离路段独立存在 (Priority: P1)

数据管理员导入 `.STA` 桩号序列文件时，桩号锚定在**路线/设计项目**上，而不是锚定在某个路段下。路段的建立、调整、删除都不影响已导入的桩号。

**Why this priority**: 这是本 spec 的根。桩号是全部设计文件的公共坐标，`geometry_point`、横断面、土方、超高、路幅全部以它为锚。锚错了，上层全错 —— 而错误会以「行数对但桩号错位」的形式静默传播。

**Independent Test**: 让 `station_sequence.section_id` 可以为空；导入 `.STA` 后，即使没有任何 `road_section` 记录，332 个桩号仍然完整存在。

**Acceptance Scenarios**:

1. **Given** 库中不存在任何 `road_section`，**When** 导入 `.STA`（332 个桩号），**Then** 332 个桩号全部入库，且各自的路线归属正确可查。
2. **Given** 已导入 332 个桩号且挂在某路段下，**When** 该路段被调整（改名/改边界），**Then** 桩号不受影响（不改动、不被级联删除）。
3. **Given** 两个路段桩号区间相差 4635 km，**When** 查询「全路线桩号」，**Then** 能按路线分别返回各自的桩号集合，不混淆。

---

### User Story 2 - 文件覆盖区间被记录，越界即报错 (Priority: P1)

导入任何设计文件时，系统记录该文件的**桩号覆盖区间**，并校验它是否落在其声明的范围内。越界**报错并拒绝入库**，不静默丢弃。

**Why this priority**: 实测已发现真实的越界风险 —— `.STA` 到 **K5+805.421**，而 `.WID`（路幅宽度）只到 **K5+701.461**，**短 103.96 m**。若不校验，`geometry_point` 的最后 104 米会凭空生成或静默丢失，而两种结果都不会报错。

**Independent Test**: 导入一个覆盖区间超出声明范围的文件，导入必须失败并给出越界的具体桩号与差值。

**Acceptance Scenarios**:

1. **Given** `design_file` 记录了某文件的覆盖区间，**When** 导入该文件，**Then** 实际解析出的桩号区间与记录区间一致，否则导入失败。
2. **Given** 某文件的实际覆盖短于其声明（如 `.WID` 短 103.96 m），**When** 导入，**Then** 系统明确报出缺失区间与长度，不静默补值。
3. **Given** 一次导入失败，**When** 查看结果，**Then** 库中没有该文件的任何部分数据。

---

### User Story 3 - 桩号文本与数值可互相还原 (Priority: P1)

每条桩号记录的**文本形式**（`K0+020.000`）与**数值形式**（`0.020` km）必须能互相解析还原。任一条记录不一致即为错误。

**Why this priority**: 两列独立存储、无约束（实测 332 行恰好全部相等，但那是因为数据干净，不是因为机制保证）。桩号一旦错位，所有按桩号对齐的操作都会得到看似合理但错误的结果。

**Independent Test**: 构造一条 `station_text` 与 `station_local_km` 不符的记录，校验必须拒绝它。

**Acceptance Scenarios**:

1. **Given** 一条桩号记录，**When** 校验，**Then** 文本解析出的数值等于数值列。
2. **Given** 一条文本与数值冲突的记录，**When** 导入，**Then** 导入失败并指出该行。

---

### User Story 4 - 逐桩线形（κ/G/E）生成 (Priority: P2)

在桩号基准就位后，从已接收的 `.PM`/`.JD`/`.DMX`/`.ZDM` 生成 `geometry_point` 的 332 行逐桩线形：曲率 κ、纵坡 G、高程 E。

**Why this priority**: 这是本 spec 的产出目标，也是 TruckSim / FEM 的公共输入。排在 P2 是因为**它的正确性完全依赖 P1 的桩号基准** —— 桩号错了，算出来的 κ/G/E 再精确也是错的。

**Independent Test**: 生成 332 行 `geometry_point`，与 `.STA` 桩号逐行对齐，抽样比对设计高程。

**Acceptance Scenarios**:

1. **Given** 桩号基准与源文件就位，**When** 生成，**Then** `geometry_point` 得 332 行，与 `station_sequence` 一一对应（无多、无少、无错位）。
2. **Given** 生成完成，**When** 抽查某桩号，**Then** 其设计高程与 `.ZDM` 一致。
3. **Given** 某桩号在源文件中无数据（如 `.WID` 覆盖不到的最后 104 m），**When** 生成，**Then** 该字段为 NULL 并附说明，不得填 0 或外推。

---

### Edge Cases

- **路段与桩号无交集**：路段 1 声明 K4635~K4654，桩号在 K0~K5.8，二者无交集。系统不得因此报错或强行关联，应如实报告「无交集」。
- **断链尚未发生**：实测 `station_equation` 为 0 行，故 `station_local_km` 与 `station_absolute_km` 恒等（332/332）。两列是**为断链预留**的，当前冗余是**正确**的，不得据此删除其一。
- **同一桩号出现两次**：断链点前后可能重号。系统须能承载，不得用唯一约束误杀。
- **空桩号文件**：`.STA` 解析出 0 个桩号时，须报错，不得当作「成功导入 0 行」。
- **桩号类型**：实测 290 整桩 + 40 加桩 + 2 端点 = 332。加桩（非整数米）不得被规整到整桩。

## Requirements *(mandatory)*

### Functional Requirements

#### 桩号基准（P1）

- **FR-001**: 系统 MUST 允许桩号序列**独立于路段**存在 —— `station_sequence.section_id` 必须**可为空**，且桩号的路线归属可另行表达。
- **FR-002**: 系统 MUST 保证路段的新增/修改/删除**不影响**已导入的桩号；删除路段 MUST NOT 级联删除桩号。
- **FR-003**: 系统 MUST 能按**路线**分别查询桩号集合，使桩号区间相差数千公里的两条路线互不混淆。
- **FR-004**: 系统 MUST NOT 假定「路段之并等于路线全桩号」；桩号集合的完备性 MUST 以桩号文件自身为准，不以路段覆盖为界。

#### 覆盖区间校验（P1）

- **FR-005**: 导入任一设计文件时，系统 MUST 记录该文件实际解析出的桩号覆盖区间（起、止），写入 `design_file.coverage_from_station_km` / `coverage_to_station_km`。
- **FR-006**: 当文件的实际覆盖区间与其声明区间不符时，系统 MUST 导入失败，并报出：文件、声明区间、实际区间、差值（米）。
- **FR-007**: 导入失败时，该文件 MUST NOT 有任何部分数据入库（原子性）。
- **FR-008**: 系统 MUST NOT 对缺失区间做任何补值、外推或默认填充。

#### 桩号一致性（P1）

- **FR-009**: 每条桩号记录的文本形式与数值形式 MUST 可互相解析还原；不一致时导入失败并指出具体行。
- **FR-010**: 桩号校验 MUST 覆盖**全部**记录，不得只抽样；且 MUST 有一条元测试证明「坏数据会被拒绝」。
- **FR-011**: 系统 MUST 保留桩号类型（整桩/加桩/端点），加桩 MUST NOT 被规整。

#### 逐桩线形（P2）

- **FR-012**: 系统 MUST 能生成 `geometry_point` 的逐桩线形，桩号与 `station_sequence` 逐行对应。
- **FR-013**: 生成的每一行 MUST 可追溯到其源文件；源数据缺失时 MUST 为 NULL 并附原因，MUST NOT 填 0 或外推。
- **FR-014**: 生成结果 MUST 可按桩号区间查询，供 TruckSim / FEM 消费。

### Key Entities

- **桩号 (station)**: 路线上的一个客观里程位置。关键属性：数值桩号、文本桩号、桩号类型（整桩/加桩/端点）。**独立于路段存在**，是全部线形数据的公共坐标。
- **桩号体系 (station system)**: 一条路线上全部桩号的集合，含断链定义。完备性由桩号文件决定，不由路段划分决定。
- **路段 (road section)**: 路线的**管理划分**，是对桩号区间的一种标定。允许有洞、允许调整、长度不定。**不得**反过来界定桩号。
- **文件覆盖区间 (file coverage)**: 某个设计文件实际覆盖的桩号范围。不同文件的覆盖区间**可以不同**（实测 `.STA` 与 `.WID` 相差 103.96 m），此差异必须被记录而非被抹平。
- **逐桩线形 (geometry point)**: 每个桩号上的线形量：曲率 κ、纵坡 G、设计高程 E 等。派生于桩号基准与源文件。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在不建立任何 `road_section` 的前提下，可完整导入并查询一条路线的全部桩号（332/332 行）。
- **SC-002**: 桩号区间的**完备性**可被机械验证：对任意设计文件，其实际覆盖区间与声明区间的一致性有明确结论（一致或差多少米），不存在「不知道」。
- **SC-003**: 100% 的桩号记录通过文本-数值互还原校验；坏数据（构造的）100% 被拒绝。
- **SC-004**: `geometry_point` 行数与 `station_sequence` 行数**严格相等**（332），且逐行桩号一致。
- **SC-005**: 任何因数据缺失而未能生成的字段，在**结果中显式可见**（NULL + 原因），不出现静默的 0 或外推值。
- **SC-006**: 新增的校验均配有元测试，证明「坏数据确实会被拒绝」—— 杜绝空转通过。

---

## Assumptions

- **桩号锚定到路线而非设计项目**：因为实测设计项目只有 1 条，而路线有 5 条，桩号属于「路线」这个更稳定的层级。此假设如需变更，属架构决策，走工单。
- **`.STA` 是桩号基准的真源**：`.PRJ` 与其一致（均 0.000~5805.421），`.WID` 短 103.96 m 属被校验方而非基准方。
- **断链表当前为空是正常状态**：实测 `station_equation` 0 行，故 local 与 absolute 恒等；这不是缺陷，是断链尚未发生。
- **`geometry_point` 的 332 行目标**：来自 `station_sequence` 的实测行数，与 `.STA` 的 0.000~5805.421 一致。

## 依赖与风险

| 项 | 说明 |
|---|---|
| **依赖 feature 001** | 缺口归因框架已就位，`geometry_point` 已从「unknown」正确归因为「该段写适配器」 |
| **架构决策风险** | FR-001 改动 `station_sequence` 的外键方向（`section_id` 可为空 ＋ 新增路线锚定），**触碰现有表，属契约②变更，须走工单由导师把关** |
| **迁移风险** | 现有 332 行桩号需从 section 6 迁移到路线锚定；迁移 MUST 可回滚 |
| **数据缺口** | `.WID` 短 103.96 m；`横断面绘图.3DR` 缺失（`absent`）；`design_file.coverage_*` 当前全为 NULL |
