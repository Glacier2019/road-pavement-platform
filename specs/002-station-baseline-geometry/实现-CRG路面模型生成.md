## 2. ★ 必须遵守的 5 条格式规则

全部依据 `c-api/baselib/src/crgLoader.c` 源码（v2.0.1 tag，与 v1.1.2 同源）。
手写 `.crg` 时**任何一条不满足都会被静默或半静默地拒绝**。

### 2.1 数据段起始标记是 `$$$$`，不是 `$KD_DEFINITION`

```c
{ "$KD_DEFINITION", setSection, dFileSectionDataDef     },
{ "$$$$",           setSection, dFileSectionDataContent },
```

`parseFileHeader()` 只在 `sectionType == dFileSectionDataContent` 时才把控制权交给数据段。
只有 `$KD_DEFINITION` 的反面后果是：

```
NOTICE: crgLoaderAddFile: this file contains no data section.
```

### 2.2 `$$$$` 之前必须有一个单独的 `$` 行

`setSection()` 的硬性守卫：

```c
if ( (crgData->admin.sectionType == dFileSectionNone) || (newSection == dFileSectionNone) ) {
    crgData->admin.sectionType = newSection;
    ...
}
return 0;    /* 当前段非 None 且新段非 None → 什么都不做 */
```

正确顺序是**三行**：先 `$` 结束 `$KD_DEFINITION`，再 `$$$$` 开数据段。

```
$
$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$$
```

### 2.3 ASCII 必须用 `K`(compact)，不能用 `L`(long)

```c
if (admin.dataFormat & dDataFormatLong)
    recordSize = ( ( recordSize / 80 + 1 ) * 80 );   /* 强制定长 80 字节整数倍 */
```

`L` 让 loader 按固定字节数跳行，而 ASCII 行是变长的 → 行错位、`z` 全为 `nan`、
u 范围被截断（实测只读到 4 行，u 范围 0..0.3 m）。

格式码只认三个字母，`I` 无作用：`L`/`K`、`D`/`S`、`F`/`B`。

> **ASCII + double + compact 的正确写法是 `#:KDF`。**

### 2.4 ASCII 每字段必须定宽 20 字符（最难发现的一条）

```c
if (admin.dataFormat & dDataFormatASCII)
    length = (admin.dataFormat & dDataFormatPrecisionDouble) ? 20 : 10;
...
while ( (*dataPtr == '\n' || *dataPtr == '\r') && nBytesLeft ) { ... }  /* 不跳空格 */
strncpy( tmpStr, dataPtr, length );      /* 每 20 字符硬切一刀 */
value = atof( tmpStr );
dataPtr += length;
```

**它不按空白切分，而是每 20 字符一刀硬切。**因此：

- 每行长度必须 `== 20 × 通道数`
- 每个值左对齐补齐到 20 字符
- 空格分隔的变长数字会被完全解析错

### 2.5 `U:` 行是声明性的，不填充字段

```c
{ "U:", decodeIndependent, dOpcodeNone },   /* decodeIndependent 是空操作 */
```

u 轴实际由头段 `REFERENCE_LINE_START_U` / `_END_U` / `_INCREMENT` 决定，
且首行 u 取自数据段第一列。头段关键字匹配用 `crgStrBeginsWithStrNoCase`，
**大小写不敏感**。

## 4. 线形与高程的重建规则

### 4.1 平面线形

`phi` 通道存**绝对方位角（弧度）**，loader 自行积分出 x/y：

```
NOTICE: calcRefLine: Reference line will be generated by integration of phi values.
```

段内方位角按**曲率线性**积分（真回旋线）：

```
κ(s) = k0 + (k1 − k0)·s/L
az(s) = az0 + k0·s + (k1 − k0)·s²/(2L)
```

- 直线：κ = 0
- 圆曲线：κ = ±1/R
- 缓和曲线：入口 ∞→R 时 k0=0, k1=±1/R；出口 R→∞ 时 k0=±1/R, k1=0

**★ 缓和曲线方位角变化量是 `Δaz = L/(2R)`，不是 `L/R`。**
**★ 曲率列无符号，方向必须由 Δazimuth 判定。**
**★ 半径列只填一端：入口填 `radius_end_m`，出口填 `radius_start_m`；
`radius_start_m IS NULL` 唯一判定入口。**

> 若对缓和曲线改用「方位角线性插值」，会产生 2.31 m 误差且**不随步长收敛**
> （模型误差，非数值误差）。

### 4.2 纵断面

`profile_grade_point` 12 个 VPI，竖曲线为抛物线：

```
T  = |Δg|·R/2        （切线长）
Lc = |Δg|·R          （曲线长）
z(s) = z_vpi + g1·d + (g2 − g1)/(2·Lc)·d²      , d = s − s_vpi, |d| ≤ Lc/2
```

实测高程落差 29.750 m（54.064 ~ 83.814 m），坡度 −5.0% ~ +6.0%。

### 4.3 采样轴必须用连续里程

以 `0, 0.1, 0.2, … 5805.4, 5805.421` 为轴线 → **58,055 点**。
若逐段 `round(L/STEP)` 会丢 1 点（58,054），并在段边界造成 0.1 m 的 u 轴平台。

### 4.4 横向 v 必须对称覆盖半幅

列数用 `int(round(2·vmax / VINC))`，否则末列会少一个增量
（实测 `4.25` 退化成 `4.15`）。

## 5. 两套独立实现的交叉印证

| 实现 | 终点 x | 终点 y |
|---|---|---|
| Python（中点法积分） | −4521.325 | 3120.210 |
| OpenCRG 官方库（phi 积分） | −4521.122 | 3119.874 |
| 库中 `alignment_element` 末段 `end_x/end_y` | −4521.335 | 3120.229 |

两者相差 **0.39 m**（5.8 km 上），各自与库中真值相差约 0.02 m / 0.41 m。
两个独立实现互相印证，说明格式与积分模型均正确。

> 偏差量级与 `验证-路线线形0.1m分辨率可生成性.md` 中已定位的
> 「坐标列与里程列之间 ~1e-06 相对尺度差」同源。**结论不变：不重写数据。**

## 6. 环境与依赖

- **必须用 hlrs-vis/opencrg v1.1.2**，这是 Chrono 官方
  `contrib/build-scripts/linux/buildOpenCRG.sh` 硬编码的版本。
- v1.1.2 用 **makefile 而非 CMake**；`make` 前必须先 `mkdir -p obj lib`。
- v1.1.2 的 `CFLGS` 含 `-ansi`（C90），而源码内有 `//` 注释 →
  现代 GCC 报 `C++ style comments are not allowed in ISO C90`。
  **改用 `-std=gnu99` 即可。**
- 装到仓库外的 `$HOME/Packages/openCRG`，**不要进本仓库**（保持干净可分发）。

## 7. 与 Chrono 的衔接

`CRGTerrain` 可加载本文件，且其类参考明确说明：

> Concrete class for a (rigid) road loaded from an OpenCRG file.
> This type of terrain can be used in conjunction with tire models that perform
> their own collision detection (e.g., ChTMeasy, ChPac89, ChPac02, ChFiala).

**★ CRG 路面不含碰撞/接触信息，只能配半经验轮胎模型**——与
`评估-Chrono替代TruckSim.md` §2.1「半经验轮胎仅适用平坦路面」直接相关。
要做到可变形路面（SCM）必须换路面表示。

相关 API（已按官方类参考核对）：

- `void UseMeshVisualization(bool)` — true = mesh（路面带），false = boundary（边界曲线）
- `void ExportMeshWavefront(const std::string& out_dir)`
- `std::shared_ptr<ChBezierCurve> GetRoadCenterLine()` / `GetRoadBoundaryLeft/Right()`
- `double GetLength()` / `GetWidth()` / `bool IsPathClosed()`

## 8. 本机限制（重要）

本开发沙箱**无法进行任何 GL 渲染**：`/dev/dri` 与 `/dev/nvidia*` 均不存在、
capabilities 全 0、`sudo` 被 `no-new-privileges` 禁用。

离屏 EGL 即使强制软件光栅化（`LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe`）
也在 `eglCreateContext` 阶段失败（`0x3004 EGL_BAD_ATTRIBUTE`），因为 Mesa 仍需 DRI 通道。

**纯 CPU 工作不受影响**：`.crg` 生成、格式校验、网格/中心线导出、官方库读取
全部可在沙箱内完成并验证。**可视化窗口必须在有 GPU/显示的宿主侧运行。**
