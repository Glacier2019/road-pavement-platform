## 0. 摘要（给导师的一页）

**问题**：`test_deliverable_truth.py` 的断言 A 名叫「生成脚本里零硬编码表数/DDL 版本」，
读起来像「这类风险已被守住」。**实测不是。**

**证据**（实跑，非推断）：

| 事实 | 实测值 |
|---|---|
| 扫描范围 | `docpipe/scripts/gen_*.py`，共 **11** 个脚本 |
| `gen_er.py` 是否在范围内 | ✅ **在** |
| `gen_er.py` 命中 `_FORBIDDEN` 的行数 | **0** |
| `gen_er.py` 实际硬编码的域数 | **11**（现状 7 域） |
| `gen_er.py` 页脚写死的版本 | `DDL v0.3`（现状 v0.6） |

即：**一份把 11 域旧模型整个写死在代码里的脚本，从守卫底下走了过去。**

**改法**：把「禁止几个字符串」升级为「把脚本里声明的模型拿去和真源**比对**」，
并配元测试（宪法原则 V：新检查必须证明自己会红）。

## 1. 为什么要走这张工单

### 1.1 宪法原则 V 的直接要求

> **一个永远不会失败的检查，比没有检查更糟。**

断言 A 现在就是这种状态 —— 不是「永远不会失败」（它对某些输入确实会红），
而是**对它声称覆盖的那一类风险不设防**。这比纯粹的摆设更坏：
摆设一眼看得出来，而它会让所有人（包括我）以为已经守住了。

### 1.2 本轮已经因此误判过一次

我在写 `gen_er.py` 的遗留登记时，第一反应是「有断言 A 在，这件事有守卫」，
**实际跑了一遍才发现命中 0 行**。登记里那句「目前没有任何自动化手段会发现它过期」
是查到之后才敢写的。

这正是本工单的第一条依据：**我作为「知道这条检查存在的人」都误判了，别人只会更甚。**

### 1.3 旧模型图的价值与风险并存

按前置核查的结论：`gen_er.py` 记的是**当年的设计意图**（设计文档版），
不是「过期的现状」，所以**不该删**。但也不该让它默默躺在那儿 ——
它现在的状态是「内容正确（作为历史）、标注缺失（作为现状）」，
而缺标注正是会误导人的那一半。

## 2. 现状核查（改之前的事实）

### 2.1 三条禁止模式的实际形状

```python
_FORBIDDEN = [
    (re.compile(r"物理\s*\d+\s*表"),           "硬编码物理表数"),
    (re.compile(r"10_ddl_v\d+\.\d+\.sql"),    "硬编码 DDL 文件名"),
    (re.compile(r"EXPECTED_TABLES\s*=\s*\d+"), "硬编码期望表数"),
]
```

### 2.2 为什么 `gen_er.py` 三条都不命中

| 模式 | 要求 | `gen_er.py` 实际写的 | 命中 |
|---|---|---|---|
| `物理\s*\d+\s*表` | 形如「物理 35 表」 | 表名逐个列在 `t('road_line','GE',...)` 里，**从不写总数** | ❌ |
| `10_ddl_v\d+\.\d+\.sql` | 形如「10_ddl_v0.3.sql」 | 只写 **`DDL v0.3`**（裸版本号，无文件名） | ❌ |
| `EXPECTED_TABLES\s*=\s*\d+` | 变量赋值 | 用 `T = {}` + `t()` 累积，**无字面量总数** | ❌ |

**三条模式全都建立在「作者把总数写成了一个字面量」这个假设上。**
而 `gen_er.py` 的做法完全不同：它把模型**结构化地**表达出来（每张表一次调用）。
结构化表达反而比字面量更危险 —— 它**不会被字符串匹配发现**，却同样会过期。

### 2.3 ★ 第二个空洞：一条不可见的硬编码豁免

断言 A 的循环里有一行：

```python
for f in _GEN:
    if f.name == "gen_ddl_v03.py":
        continue          # ← 按文件名豁免
```

即有一个脚本被**按文件名跳过**。理由可以理解（它是工单 #2 的一次性实施脚本，
产物就是今天的 DDL），但这个豁免：

1. **不可见** —— 不看代码就不知道；断言名里也没提；
2. **不可证伪** —— 没有任何测试钉住「豁免名单只有这一个」，
   下次有人想放过一个真有问题脚本，加一行 `if f.name == ...: continue` 就行了；
3. 与 §2.2 的空洞**同源**：都是「用一个宽松的判据换取了绿」。

### 2.4 元测试的覆盖缺口

断言 C 现有 4 条元测试，测的都是**文档侧**（`_scan_line` / `_is_historical`）。
**断言 A 没有任何元测试** —— 没有任何一条测试证明「硬编码旧模型的脚本真的会被抓出来」。

## 3. 变更内容

### 3.1 新增：域集合一致性检查（核心）

**判据**：`docpipe/scripts/` 下任何**声明了域集合**的脚本，其声明的域集合
必须与真源 `catalog.py` 的域集合一致。

真源取法（与既有 `contract_truth` 同一约定，**不写死**）：

```python
from rpdao.catalog import DOMAINS   # 域分组唯一真源
truth_domains = set(DOMAINS)        # 现状 {'GE','SU','RE','LO','WE','TE','DE'}
```

脚本侧取法：解析 `'([A-Z]{2})':` 形式的域代号字面量。

**为什么这条能抓住 `gen_er.py`**：它声明 11 个域，真源 7 个，差集非空 ⇒ **红**。
而 §2.2 那三条字符串模式永远抓不住它 —— 判据从「文本长什么样」
变成了「声明的模型与真源是否一致」。

**边界**：只对**确实声明了域**的脚本生效（域数 ≥ 1）；
`gen_ddl_v03.py` / `gen_arch_figures.py` 等声明 0 个域，不适用于本条。
这不是网开一面 —— 它们本来就不表达域模型，是**适用性判断**，见 §3.4。

### 3.2 新增：豁免名单必须显式且被钉住

把 §2.3 那行内联 `continue` 提成一个**带注释的显式常量**：

```python
#: 按定义不适用「从真源读」的脚本。每一条都必须写明理由，
#: 且下面有元测试钉住名单长度 —— 它只能变短，不能悄悄变长。
_EXEMPT = {
    "gen_ddl_v03.py": "工单 #2 的一次性实施脚本，产物即今日 DDL；不动它",
}
```

配套一条元测试：**豁免名单不许增长**（断言长度 ≤ 1，且键就是那一个）。

> 这与既有 `_is_historical` 白名单的处理方式**同构** ——
> 那个白名单已经有「白名单不许无限膨胀（<= 1/3 文档）」钉住。
> 本处只是把同一套纪律搬到脚本侧，不发明新机制。

### 3.3 新增：断言 A 的元测试（补 §2.4 的缺口）

至少三条，全部用**临时构造的假脚本**，不依赖真实文件：

| # | 构造 | 期望 |
|---|---|---|
| 1 | 一份声称 11 域（真源 7）的脚本 | ✅ **被判定为不一致** |
| 2 | 一份声称 7 域（与真源一致）的脚本 | ✅ **不被误报** |
| 3 | 一份内联 `if f.name == ...: continue` 的豁免 | ✅ **被认出并报告** |

第 3 条尤其重要 —— 它钉的是 §2.3 那个**不可见的豁免**：
任何人再想加一行内联跳过，元测试会红。

### 3.4 明确不做

| 不做 | 理由 |
|---|---|
| 改 `gen_er.py` 的模型内容 | 它记的是当年的设计意图，改动即销毁证据 |
| 删 `gen_er.py` | 同上；且删除他人产物需单独授权 |
| 给 `gen_ddl_v03.py` 补真源接入 | 它已执行完毕，改它没有意义，只会制造噪音 |
| 新增 DDL/表/列 | 本工单不碰数据库 |

## 4. 影响面

### 4.1 本工单会让既有测试**变红**（这是预期结果）

新增检查一旦落地，`gen_er.py` 会立刻被判定为「声明的域 ≠ 真源域」。

**这不是缺陷，是本工单的价值所在** —— 它把一个一直存在、
但无人知晓的事实变成了红灯。处理方式：

| 方案 | 做法 | 评价 |
|---|---|---|
| **甲（推荐）** | 把 `gen_er.py` 加入 `_EXEMPT`，理由写「设计文档版，记录历史口径」 | 与 §3.2 的豁免纪律一致；豁免显式且有元测试钉住 |
| 乙 | 在甲的基础上，给 `gen_er.py` 文件头加一行醒目标注 | 更清楚，推荐与甲同做 |
| 丙 | 不许豁免，迫使脚本改从真源读 | ❌ 会销毁「当年打算做什么」这条信息 |

**建议甲+乙**：豁免 + 文件头加一行说明。既不销毁历史，
也让下一个打开它的人第一眼就知道该看什么。

### 4.2 不影响的范围

- 不动 DDL、DAO、OpenAPI ⇒ 其余 17 条契约测试不受影响；
- 不动 `docpipe/` 下任何脚本的**行为**（只可能加注释）；
- `_GEN` 扫描范围不变（仍是 11 个脚本）。

## 9. 实施记录（2026-09-20）

Q1–Q3 三项均按建议通过并已实施。改动集中在**一个文件**：
`scaffold/tests/contract/test_deliverable_truth.py`。

### 9.1 改了什么

| # | 变更 | 位置 |
|---|---|---|
| 1 | 新增 A2：声明的域集合必须等于真源 | `main()` 断言 A 之后 |
| 2 | 内联豁免 → 显式常量 `_EXEMPT` | 常量区 |
| 3 | 新增 `_truth_domains()` / `_declared_domains()` / `_INLINE_SKIP` | 常量区 |
| 4 | 新增 5 条断言 A 的元测试（A1–A5） | 断言 C 之后 |
| 5 | 文档字符串补上 A2 的说明 | 文件头 |

### 9.2 关键实现决定

**★ 真源不写死。** `_truth_domains()` 通过 `importlib` 加载
`scaffold/modules/M3-rpdao/rpdao/catalog.py` 取 `DOMAINS` 的键。
若在这里写一个 `{"GE","SU",...}`，本检查自己就会变成下一个
「硬编码旧模型」—— 那正是它要防的东西。并有一条元测试（A5）钉住这一点。

**★ 元测试不写死 11/7。** A1/A2 用**真源域**加减构造假脚本
（`truth_doms | {"ZZ","YY"}` 与 `truth_doms`），不写数字。
写死的话，将来域集合一变，元测试自己就失效了 —— 而它失效时不会有人发现。

**★ 适用性判断 ≠ 豁免。** A2 只对**确实声明了域**的脚本生效
（`_declared_domains(f)` 非空）。实测 11 个 `gen_*.py` 里**只有 `gen_er.py`
声明了域**（11 个），其余 10 个都是 0 个 —— 它们本来就不表达域模型。
这是「这条规矩不适用于它」，不是「放它一马」；放一马的走 `_EXEMPT`。
两者刻意分开，因为处置方式完全不同。

### 9.3 豁免名单（Q1 裁决的执行）

```python
_EXEMPT = {
    "gen_ddl_v03.py": "工单 #2 的一次性实施脚本，产物即今日 DDL；不改它",
    "gen_er.py": "设计文档版：记录当年的完整设计意图……文件头已加醒目标注。",
}
```

比工单原计划多了一条：原 §3.2 只写了 `gen_ddl_v03.py` 一条，
`gen_er.py` 是 §4.1 甲案要求新增的。**两条都有理由，且元测试 A4 钉住总数**
（`len(_EXEMPT) <= 2`）—— 名单只许变短。

### 9.4 ★ 验证：证明检查真的会红，而不是被豁免遮住

这是本节最重要的一条。新检查跑绿时，它显示的是
「生成脚本声明的域集合等于真源（7 域）」—— 但 `gen_er.py` **在豁免名单里**，
所以「绿」本身**不能证明检查有效**。绿可能是因为检查根本没在跑。

直接验证（把豁免拿掉看它怎么判）：

```
gen_er.py 在 _EXEMPT 中: True
声明: 11 域 ['DE','FA','GE','LO','QU','RE','SA','SE','SU','TE','WE']
真源:  7 域 ['DE','GE','LO','RE','SU','TE','WE']
相等吗: False     多出: ['FA','QU','SA','SE']     缺少: []
=> 检查会判与它不一致：True
```

即：**豁免在遮住一个真实的红，而不是遮住一个不工作的检查。**
这两者从测试输出上完全看不出来，所以必须显式验证并写在这里。

### 9.5 元测试清单（全绿）

```
  OK   元测试-A1：声明域 ≠ 真源的脚本被认出（不是摆设）
  OK   元测试-A2：声明域 == 真源的脚本不被误报（不狼来了）
  OK   元测试-A3：内联的文件名豁免被认出（工单 #4 §2.3 那个空洞）
  OK   元测试-A4：豁免名单未膨胀（只许变短）
  OK   元测试-A5：真源域取自 catalog.py，未写死
```

A1 与 A2 **成对**：只有 A1 会引诱人把判据写严到「凡声明域就报错」；
只有 A2 则证明不了检查有效。这与 `test_coverage_check.py` 里每条
FR-005/006/008 断言都配证伪对照，是同一套纪律。

A4 是防「用豁免换绿」的那一条 —— 没有它，`_EXEMPT` 自己会变成下一个内联 `continue`。

### 9.6 Q3 的执行，及其一个**必须说明的限制**

已按 Q3 给 `gen_er.py` 文件头加了一段醒目标注，写明：它是设计文档版、
声明 11 域、当前真源 7 域 62 表 DDL v0.6、页脚 `DDL v0.3` 是历史口径**未改**、
以及它已被 `_EXEMPT` 豁免且豁免处有元测试钉住。

⚠ **但这个标注不会被提交。** 实测：

```
$ git check-ignore -v docpipe/scripts/gen_er.py
.gitignore:57:docpipe/scripts/*    docpipe/scripts/gen_er.py
```

`docpipe/scripts/*` 整体被忽略（只有 `gen_er_weidi.py` 有 `!` 例外）。
因此该标注**只存在于本机**，别人克隆仓库后看不到。

这意味着 Q3 的目标（让下一个读它的人第一眼知道该看什么）
**在本机成立、在克隆仓库不成立**。要真正达成，需要二选一：

| 方案 | 做法 | 代价 |
|---|---|---|
| 甲 | 给 `.gitignore` 加 `!docpipe/scripts/gen_er.py` 例外，把文件纳入版本控制 | 与「仓库只留代码与契约」的既有决定（commit `a0dcd32`）冲突 |
| 乙 | 把该标注写进**已跟踪**的文档（如本工单或 `工程决策记录.md`） | 不在文件旁边，需要先知道去哪儿找 |
| 丙 | 接受现状：本机可见即可 | 对克隆者无效 |

**建议乙**（本工单 §9.6 与 `工程决策记录.md` 的遗留登记已经是乙的一部分），
并在将来若 `gen_er.py` 被纳入版本控制时改为甲。
