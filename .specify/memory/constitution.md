# 路面性能数智化平台 Constitution

> 本文件是**治理层**：它规定"什么算做对了"，不重复操作手册怎么做。
> 操作细节见 `scaffold/MODULE-ONBOARDING.md`（接入规约）、
> `学生上手指南-分模块开发手册.md`（上手）、`工程决策记录.md`（决策史）。
>
> **每条原则后面都跟着"机器怎么强制"**。没有强制手段的原则不写进来 ——
> 写一条没人能验的规矩，比不写更糟：它会让所有人都以为自己被约束着。

## Core Principles

### I. 契约先行，且"能跑的东西才是契约"（NON-NEGOTIABLE）

模块之间唯一的沟通方式是**四份契约**：①报文格式（`contracts/messages/*.schema.json`）
②表结构（`scaffold/sql/10_ddl_v0.5.sql`）③数据访问层（`scaffold/modules/M3-rpdao/`）
④服务接口（各服务 `/openapi.json`，`contracts/openapi/*.yaml` 为人工摘要）。

- **文档不是契约。** 任何"我口头跟你说字段改一下"一律不算；能跑、能被测试引用的才是。
- 契约**禁止就地改**：变更走工单，附版本号递增与兼容性声明。
- 契约测试必须覆盖**应通过 / 应拒绝两侧**。只有"应通过"一侧的测试，
  证明不了系统会拒绝坏输入。
- **下游不启动，直到上游的两个契约测试都绿。**

**机器怎么强制**：`run_contract_tests.sh` 总运行器（12/12 套件）；
`test_api_routes.py` 双向比对 openapi 契约与实际路由，缺任一侧即红。

### II. 三条数据硬线，且必须"结构上做不到"违反

1. **写入只经 M2** —— 七域业务数据只有 M2 能写。
2. **读只经 M3（rpdao）** —— 谁都不许自己连数据库拼 SQL 取数。
3. **跨模块只认契约** —— 模块之间不互相 import 代码。

**关键在"结构上做不到"，不是"我们约定不这么做"。**
一条只写在文档里的硬线，不是硬线。所以：M3 用 `TABLE_OWNER` 表级写权守卫，
**默认拒绝**（未登记写权的表一律写不进去 —— 默认允许意味着每加一张新表就自动多一个
无人看守的写入口）；M6/M9 不持有连接池、拿不到 cursor；M9 容器**不给 `PG_DSN`**，
连"表名"这个参数都传不进去（`table_census()` 的表名只从 `ALL_TABLES` 来）。

**机器怎么强制**：`test_write_guard.py`（应通过/应拒绝两侧）、
`test_dao_contract.py` 第 4 组（AST 断言 M6 无 psycopg）、
`test_console.py` 第 1 组（AST 断言 M9 无 psycopg + compose 无 PG_DSN）。

### III. 证据优先级：实库 > DDL 文件 > 数据字典/catalog > 图件

判断"事实是什么"时严格按此顺序，**低优先级来源与高优先级冲突时，无条件服从高优先级**。
第三方文件另有细则：**文件自己的头部 > 手册文字**；
**文件首行 ＋ 实测内容 > 网上说法 > 后缀猜测**。

这条规矩是有代价换来的：本仓库多次出现"文档说 42 表、实库有 62 表"这类漂移，
而漂移的方向**永远是文档过期，不是实库出错**。

**机器怎么强制**：`test_ddl_dict_catalog.py`（DDL ↔ 数据字典 ↔ catalog 三处表数一致）；
`test_ddl_migration_parity.py`（`DDL(全新装) == DDL + migrations(升级)`）。

### IV. 迁移是不可变历史，DDL 是全新装真相

- `scaffold/sql/*migrate*.sql` **一旦提交就不再修改**。要改就加新迁移。
- `10_ddl_v0.5.sql` 是"全新安装后应该长什么样"的唯一真相。
- **不变量**：`DDL(全新装)` 与 `DDL + 全部 migrations(升级)` 必须得到**同一套 schema**
  —— 表、列、约束、索引，**包括名字**。任何一处单独改动都必须让这条红。

**机器怎么强制**：`test_ddl_migration_parity.py`（`m1-装库一致` 套件）。

### V. 反空转：一个永远不会失败的检查，比没有检查更糟（NON-NEGOTIABLE）

这是本项目的**头号工程纪律**，因为它是唯一一种"测试全绿却什么都没验"的失败模式，
而它看起来和成功一模一样：

- **空转不是通过。** 过滤器匹配到 0 个套件时，总运行器必须**报错退出**，
  不得打印"全部通过"。`run_contract_tests.sh` 里那两条守卫，是被真实骗过一次之后加的。
- **「没去看」≠「看了没有」。** 沉默的缺失和已验证的缺失是两回事，
  报告时必须区分（`missing_not_built` vs `missing_no_data` 就是这么分开的）。
- **静默丢数据是缺陷。** 解析器能解析、但平台没有表可存 —— 这不是"待办"，
  是缺陷（`cross_section_ground_point` 就是因此才补建的）。
- **确定性不等于正确。** 一个每次都给出同样结果的实现，可能每次都错。
- 每条新增的检查，**必须配一个元测试**证明"违规时它真的会红"。

**机器怎么强制**：各契约测试里的 `元测试：…必须被认出来（非摆设）` 系列
（`test_console.py`、`test_dao_contract.py`、`test_design_import.py` 等均有）。

## 接入约束（Additional Constraints）

任何要接入平台的模块，必须**认契约 + 交五件套 + 过门禁**，三样缺一不算接入。
五件套逐条可验：①Dockerfile＋compose 服务段（含 healthcheck）②`/healthz`＋`/metrics`
③配置全外置（代码里零硬编码）④契约文件提交到 `contracts/`　⑤契约测试可离线跑。

- **配置全外置**：端口、连接串、密钥一律来自环境变量或 `config/*.yaml`。
- **三库分工**：档案/关系 → PostgreSQL；高频时序（>1 Hz）→ IoTDB；文件与影像 → MinIO。
- **批次可溯源**：批量导入必须登记 `data_import_batch`，带 `truth_flag`（默认 `false`，
  由 M4 质量门晋升为真值）。
- **未标定的阈值不得用于生产判定**：凡有阈值的配置项标 `calibrated: false`，
  门禁据此**拒绝出结论**（返回 503，而不是"通过"）。
- **新增页面/资产必须同时登记进容器定义**：容器里有路由、镜像里没文件 = 线上 500、
  而宿主机测试全绿。这条已经踩过一次。

## 开发工作流与质量门（Development Workflow）

1. **先跑契约测试，再往下走**：`cd scaffold && ./run_contract_tests.sh`。
   当前基线 **12/12 绿**。
2. **一次只动一件事，验证通过再前进**；每一步都要留下可复跑的证据，而不是叙述。
3. **交付物 = 契约测试 ＋ 假数据 demo**，各组可在独立目录/分支开发。
4. **M9 集成天然排最后**：先各模块验收，最后集成。
5. **发布判据**：`docker ps` 全部 healthy ＋ 契约测试全绿 ＋ 至少一条真实链路端到端跑通。
6. **提交信息要写"为什么"**，尤其是"这里踩过什么坑、改动后靠什么防住"。
   只写"修改了 X"不算。

## Governance

- 本宪法**高于**其它一切实践约定；与操作手册冲突时以本宪法为准。
- **修订程序**：提出 → 说明动机与影响面 → 更新版本号 → 同步受影响的模板与契约测试。
- **版本策略**（语义化）：
  - **MAJOR**：删除或重定义某条原则（向后不兼容）。
  - **MINOR**：新增原则或实质性扩展。
  - **PATCH**：措辞澄清、错别字、非语义调整。
- **合规审查**：每次改动都要跑 `./run_contract_tests.sh`；
  新增/修改契约时必须两侧都有测试；新增检查必须配元测试。
- **发现文档与实库不一致时**：以实库为准，**修文档**，并在 `工程决策记录.md` 留一条。
